Overview

What is Spark?

Spark is an AI-powered NAFPro Atlas capability that accelerates test automation from requirements.

Instead of manually writing scenarios and Gherkin from a BRD, Spark's AI pipeline analyzes your requirements, generates intelligent test scenarios, and produces automation-ready outputs using your existing NAFPro Atlas reusable steps — so generated feature files work with your framework immediately.

How It Works

Three Simple Steps

1

Provide a BRD

Point Spark to your BRD file and specify the module name. Spark's AI reads the requirements and begins intelligent flow analysis.

2

AI Generates Preview

Spark's AI pipeline creates preview assets in a safe location — nothing touches your framework folders yet. You get an AI-generated feature file, test data, constants template, and a readiness summary.

3

Review & Apply

Review the generated files and the REVIEW.md summary. If satisfied, run the apply command. Spark moves approved files into your NAFPro Atlas project folders.

Commands

Running Spark

All commands run via Maven. Copy and adapt these examples.

Generate from BRD

Start the AI pipeline — generates the first stage AI analysis prompt from your BRD.

mvn exec:java -Dexec.mainClass=novac.ai.spark.SparkRunner "-Dexec.args=--brd docs/MyModule.md --module MyModule"

Finalize AI Output

After running all 3 AI stages, finalize the output into preview assets.

mvn exec:java -Dexec.mainClass=novac.ai.spark.SparkRunner "-Dexec.args=--finalize gherkin-output.json --module MyModule"

Apply to Framework

Move reviewed assets from preview into your project folders.

mvn exec:java -Dexec.mainClass=novac.ai.spark.SparkRunner "-Dexec.args=--apply MyModule"

Check Status

See which modules have pending reviews.

mvn exec:java -Dexec.mainClass=novac.ai.spark.SparkRunner "-Dexec.args=--status"

Clean Preview

Remove preview files for a module.

mvn exec:java -Dexec.mainClass=novac.ai.spark.SparkRunner "-Dexec.args=--clean MyModule"

Tips

Best Practices

📖Write clear BRDs — Include screens, fields, validations, and business rules. Better input = better output.
👀Always review REVIEW.md — It tells you exactly what's ready and what needs manual work.
🎯Fill locators before running — Constants are templates. Every field needs a real XPath or CSS selector.
✅Validate business rules — Confirm generated scenarios cover the rules your domain expert cares about.
🔄Check test data values — Spark generates realistic samples, but verify they match your actual system.
📐Trust the reusability score — If it says READY, the feature file uses your existing steps. If LOW, investigate.
🚫Don't skip review — Never apply without reading the generated feature file. Spark assists, you approve.
